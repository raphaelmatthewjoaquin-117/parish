🔴 Complete before live traffic

Critical
Rotate the exposed Azure Storage key
The local .env is ignored by Git, but an Azure key appeared in a shared IDE/chat context. Rotate the key in Azure, update Render's secret setting, and verify uploads. Never put the replacement in Git or chat.
Critical
Configure the Render production environment
Set NODE_ENV, FRONTEND_URL, ADMIN_TOKEN, SQL Server credentials, and Azure Blob Storage credentials in Render's secret settings. Use a SQL Server with a valid TLS certificate. The API refuses production startup when the frontend origin or Azure storage is missing.
Critical
Configure Vercel to call the Render API
Set VITE_API_URL in Vercel to the public HTTPS origin of the Render API before building the frontend. Production builds reject a missing or localhost API URL.

🟡 Warnings — should fix

Warning
Check route chunk sizes on each production build
Page routes are loaded on demand to reduce the initial JavaScript download. Recheck the Vite build output after adding large features or dependencies.
Warning
Use environment settings, not a production .env
The repository includes parishweb/.env.example for local development. Production secrets belong in Render and Vercel settings; do not commit them.
Warning
Keep the Render and Vercel origins in sync
Set FRONTEND_URL in Render to the exact Vercel HTTPS origin, and set VITE_API_URL in Vercel to the Render HTTPS origin. Update both when custom domains change.
Warning
SQL Server certificate validation is required in production
Production configuration rejects DB_TRUST_SERVER_CERTIFICATE=true and defaults certificate validation to enabled. Configure SQL Server with a trusted certificate.
Warning
Keep scheduled jobs on one API instance
Finance snapshots, no-show handling, and token cleanup run in the API process. Multiple Render instances would run duplicate schedules; use one instance until jobs move to a dedicated worker.
Warning
Confirm SQL Server is reachable from Render
The API must connect to the production SQL Server during startup. Verify the SQL firewall and network allow Render to reach the configured host and port.

⚠ Repository changes improve production safety, but live readiness still depends on Render/Vercel configuration, SQL connectivity, and Azure key rotation.

Pre-deployment checklist

  • Rotate the exposed Azure Storage key, update Render's secret setting, and verify uploads
  • Set the required production environment variables in Render and Vercel
  • Set Vercel's VITE_API_URL and Render's FRONTEND_URL to the correct HTTPS origins
  • Verify Render can connect to SQL Server with certificate validation enabled
  • Keep one API instance while scheduled jobs run inside the web process
  • Run tests, lint, and the production build before deploying

Nice to have

  • Measure route chunk sizes and frontend performance on real production pages
  • Move scheduled jobs to a single worker before scaling the API horizontally
  • Run a live smoke test for database-backed pages, email, and Azure uploads
